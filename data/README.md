# Data

Every script reads from this folder by default (override with `--qilin_dir`, `--data_dir`,
`--qrels_path`, `--train_notecard_path` / `--test_notecard_path`). Expected layout:

```
data/
├── notes/train-0000{0..4}-of-00005.parquet   # Qilin notes (title, content, ...)
├── search_train/train-00000-of-00001.parquet # Qilin search training sessions
├── search_test/train-00000-of-00001.parquet  # Qilin search test sessions
├── qrels/search.test.qrels.csv               # official binary relevance labels for search_test
├── train_notecard.json                       # note cards, training/validation candidates
├── test_notecard.json                        # note cards, test pool + expanded corpus
└── test_notecard_first_pass.json             # first-pass test cards (quality audit only)
```

## Qilin

[Qilin](https://github.com/RED-Search/Qilin) (Chen et al., SIGIR 2025) is released under Apache-2.0 on
[Hugging Face](https://huggingface.co/datasets/THUIR/qilin). Only the `notes`, `search_train` and
`search_test` subsets are needed (about 1.1 GB):

```bash
python -c "from huggingface_hub import snapshot_download; snapshot_download('THUIR/Qilin', repo_type='dataset', local_dir='data', allow_patterns=['notes/*', 'search_train/*', 'search_test/*'])"

mkdir -p data/qrels
curl -L -o data/qrels/search.test.qrels.csv \
  https://raw.githubusercontent.com/RED-Search/Qilin/main/datasets/search.test.qrels.csv
```

Query ids in `search.test.qrels.csv` (`qid`) are row indices of `search_test`; document ids (`pid`) are
`note_idx` values.

## Note cards

Download `notecards.zip` from the [v1.0 release](https://github.com/Shanmin123/llm-notecards/releases/tag/v1.0)
and unzip it here:

```bash
curl -L -o notecards.zip https://github.com/Shanmin123/llm-notecards/releases/download/v1.0/notecards.zip
unzip notecards.zip -d data/
```

Each file is a JSON object that maps a Qilin `note_idx` (as a string) to the generated card text. All
cards were generated by `Qwen/Qwen3-4B-Instruct-2507` with greedy decoding
(`notecard_generation/generate_notecards.py`).

| File | Cards | Covers | Used for |
|---|---:|---|---|
| `train_notecard.json` | 92,091 | exposed candidates of `search_train[0:5000]` | training and validation |
| `test_notecard_first_pass.json` | 112,595 | top-100 exposed candidates of `search_test[0:6192]`, single generation pass | generation-quality audit (paper, Section 4) |
| `test_notecard.json` | 113,548 | the first pass plus 956 cards for exposure-pool notes of `search_test[0:1000]` that were beyond the top 100 (953) or malformed (3) | all retrieval and reranking experiments |

The 956 completion cards were generated with a shorter variant of the same prompt (two of the five
exemplars). With `test_notecard.json` the reranking pool of `search_test[0:1000]` has full card coverage
(23,621 / 23,621 notes) and the expanded retrieval corpus contains the 113,548 exposed notes of
`search_test[0:6192]` that have a card, including all 5,566 relevant notes.

A card has six lines:

```text
类目: <category>
关键词: <five keywords>
场景: <search scenario, at most 10 characters>
人群: <target audience>
实体: <brands / products / people / places, or 无 if none>
摘要: <one-sentence gist>
```

## Hard negatives for the BERT bi-encoder (optional)

`bert_hard_negatives.zip` in the same release holds the hard negatives used to fine-tune the BERT
bi-encoder in the paper (top-200 zero-shot Qwen3-Embedding-0.6B candidates of each training query minus its
positives, 32 kept per query). Unzip it into `outputs/bert_bi_retrieval/hard_negatives/` to skip the mining
step of `scripts/04_retrieval_bert_finetune.sh`.
